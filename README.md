# Twitter Sentiment Analysis

Binary sentiment classification for tweets. The project compares a lexicon baseline, six classical machine-learning models, four neural networks, a CNN feature extractor paired with an SVM, and a majority-vote ensemble — all built on one shared preprocessing and feature pipeline.

The consolidated notebook runs the complete workflow end to end: data loading, preprocessing, corpus statistics, exploratory analysis, feature engineering, training, evaluation, error analysis, and a demo on hand-written tweets. The original standalone scripts are kept under `code/` for reference.

## Overview

Sentiment analysis is treated as a binary classification problem: each tweet is either positive (`1`) or negative (`0`). Every model sees the same cleaned text and the same train/validation split, so the comparison is consistent across model families.

The pipeline:

- Loads `train.csv` and `test.csv` when they are present. Otherwise it falls back to NLTK's `twitter_samples` corpus: 4,000 tweets per class for training and 1,000 per class for testing, cached under `artifacts/samples/`.
- Cleans each tweet: lower-casing, URL and mention placeholders, hashtag normalization, emoticon tokens, punctuation and repeated-character normalization, stopword removal with negation words preserved, and optional Porter stemming.
- Builds a shared feature layer with the 15,000 most frequent unigrams, the 10,000 most frequent bigrams, frequency or presence counts, and sublinear TF-IDF.
- Holds out a stratified 10% validation split, evaluates every model with the same metrics, and writes test predictions in `id,prediction` format.
- Combines model predictions by majority vote and inspects the most confident mistakes.

## Models

| Family | Models |
|---|---|
| Baseline | Lexicon word-count baseline |
| Classical | Multinomial Naive Bayes, Maximum Entropy (NLTK), Decision Tree, Random Forest, XGBoost, Linear SVM |
| Neural | Keras logistic regression, MLP with a 500-unit hidden layer, LSTM with 128 units, CNN with four `Conv1D` layers |
| Hybrid | Linear SVM trained on 600-dimensional CNN penultimate-layer features |
| Ensemble | Majority vote over every prediction file produced by the run; ties go to negative |

The neural models require TensorFlow. If it is not installed, their sections are skipped and the rest of the notebook still runs. XGBoost is optional in the same way.

## Dataset

The notebook accepts two CSV files in the repository root:

| File | Columns | Notes |
|---|---|---|
| `train.csv` | `tweet_id,sentiment,tweet` | No header. `sentiment` is `1` for positive and `0` for negative. |
| `test.csv` | `tweet_id,tweet` | No header. Used to write prediction files. |

Tweets are quoted and may contain commas, so the notebook parses them with Python's `csv` module rather than splitting on commas.

If the files are missing, the notebook uses NLTK's `twitter_samples` corpus. It shuffles each class with a fixed seed, keeps 4,000 tweets per class for training and 1,000 per class for testing, and caches the generated CSVs in `artifacts/samples/`. If NLTK data cannot be downloaded, a small synthetic corpus keeps the notebook executable.

The word lists in `dataset/positive-words.txt` and `dataset/negative-words.txt` are used by the lexicon baseline and by the synthetic fallback.

## Setup

```bash
git clone <https://github.com/MAX9394/Twitter-Sentiment-Analysis.git>
cd twitter-sentiment-analysis

python -m venv .venv
```

Activate the environment on Windows:

```powershell
.venv\Scripts\Activate.ps1
```

On macOS or Linux:

```bash
source .venv/bin/activate
```

Install the core packages:

```bash
pip install numpy pandas scipy scikit-learn matplotlib nltk
```

Install the optional packages when needed:

```bash
pip install xgboost tensorflow
```

Download the NLTK resources (the notebook also attempts this automatically):

```bash
python -c "import nltk; nltk.download('twitter_samples'); nltk.download('stopwords')"
```

## Usage

Open the consolidated notebook:

```bash
jupyter notebook twitter_sentiment_analysis.ipynb
```

Run all cells from top to bottom. The notebook automatically uses `train.csv` and `test.csv` from the repository root when they exist; otherwise it uses the NLTK fallback. Generated files are written under `artifacts/`.

To use your own data, place the two CSV files in the repository root before running the notebook:

```text
train.csv
test.csv
```

## Legacy scripts

The `code/` directory contains the original model-by-model implementation. Use hard-coded relative paths near the top of each file, and should be run from inside `code/`.

Prepare the data first:

```bash
cd code
python preprocess.py ../train.csv
python stats.py ../train-processed.csv
```

`preprocess.py` writes `../train-processed.csv`; `stats.py` writes the unigram and bigram frequency distributions next to it. After that, run any model script:

```bash
python baseline.py
python naivebayes.py
python maxent-nltk.py
python decisiontree.py
python randomforest.py
python xgboost.py
python svm.py
```

`baseline.py` is the exception to the path convention: it reads `train-processed.csv` and `test-processed.csv` from the current directory. Copy the processed files into `code/` or update the two path constants at the top of the script.

Neural scripts:

```bash
python logistic.py
python neuralnet.py
python lstm.py
python cnn.py
```

CNN feature extraction and the hybrid SVM:

```bash
python cnn.py
python extract-cnn-feats.py <saved-model>
python cnn-feats-svm.py
```

Majority-vote ensemble: place the prediction CSVs in `code/results/` and run:

```bash
python majority-voting.py
```

`utils.py` contains shared helpers for reading word lists, saving predictions, splitting data, and loading frequency distributions.

## Notes and limitations

- The bundled results are from the NLTK sample corpus. Scores on a full, noisy tweet corpus will be lower and will depend heavily on the training data.
- Sarcasm, mixed sentiment, and negation remain the main failure modes; the notebook's error analysis inspects the most confident mistakes.
- The neural sections are optional and are skipped cleanly when TensorFlow is missing.
